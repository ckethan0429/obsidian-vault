# 에이전트 위임을 위한 마케터 업무 프로세스

[[agent-workflow-governance]]의 상태 전이·증거·승인 골격을 마케터에 적용한다. 마케터도 혼자 콘텐츠를 만드는 사람이 아니라 배포 파이프라인을 가진 사람이다. 산출물은 코드가 아니라 메시지, 자산, 채널 배포, 지출, 측정이다.

> 에이전트에게 카피를 맡기는 것이 아니라, 검증 가능하고 되돌릴 수 있는 캠페인 프로세스를 맡긴다.

## 개발자 사이클과의 대응

| 개발자 | 마케터 |
|---|---|
| 온보딩 문서 | 브랜드 가이드, ICP, 금지 클레임, 경쟁사, 채널 정책 |
| 태스크 + 서브브랜치 | 캠페인 브리프 + 캠페인 ID |
| 관련 폴더 탐색 | 기존 에셋, 랜딩, 카피, CRM 세그먼트, 과거 성과 |
| 단계별 커밋 | 초안 → 카피 → 크리에이티브 → UTM/트래킹 |
| 로컬 테스트 | 프리뷰, 브랜드/법무 검사, 링크·스펙 확인 |
| 원격 푸시 + PR | 스테이징 초안 + 리뷰 요청 |
| CI | 트래킹, 링크, 클레임, 채널 스펙, 예산 한도 검사 |
| CD | 채널 게시, 광고 집행, 이메일 발송 |
| 배포 후 관찰 | CTR, CPA, 전환, 이탈, 브랜드 리스크 |

## 캠페인 사이클

### 0. 캠페인 접수
- 목표, 대상, 채널, 예산, 기간, 성공 지표를 고정한다.
- 가설을 먼저 적는다.
- 산출물: 브리프, KPI, 금지 사항, 롤백 조건.
- 게이트: 목표나 대상이 모호하면 제작을 시작하지 않는다.

### 1. 브랜드와 시장 온보딩
- 보이스, 톤, 금지 표현, 법적 클레임, 기존 캠페인, 경쟁 메시지를 읽는다.
- 도구: 브랜드 가이드, 위키, CRM, 광고 계정, 랜딩 히스토리, 검색 Agent.
- 산출물: 써도 되는 말 / 쓰면 안 되는 말.
- 게이트: 문서와 실제 계정·랜딩이 일치하는지 확인한다.

### 2. 브리프 분해와 캠페인 브랜치
- 메시지, 랜딩, 에셋, 트래킹, 배포, 측정으로 나눈다.
- 캠페인 ID를 만든다. 예: `campaign/gpu-plg-price-anxiety-2026-08`.
- 게이트: 구현 전에 가설과 채널 범위를 검토한다.

### 3. 관련 자산 탐색
- 기존 랜딩, 이메일, 광고 세트, 세그먼트, 성과가 좋았던 카피를 찾는다.
- 산출물: 재사용 자산, 실패 패턴, 영향 채널.
- 게이트: 이미 있는 것을 다시 만들지 않는지 확인한다.

### 4. 단계별 제작과 체크포인트
~~~text
1. 메시지 가설
2. 헤드라인/본문 초안
3. 크리에이티브
4. 랜딩 또는 CTA
5. UTM, 픽셀, 전환 이벤트
6. 채널별 스펙 맞춤
~~~
각 단계는 되돌릴 수 있는 초안이어야 한다.

### 5. 로컬 검증
- 브랜드 톤, 금지 클레임, 사실 확인, 링크와 CTA
- 이미지/영상 스펙, 모바일 프리뷰, UTM과 전환 이벤트
- 게이트: “괜찮아 보인다”가 아니라 체크리스트와 스크린샷을 검토한다.

### 6. 스테이징과 리뷰 요청
- 미리보기 URL, 광고 초안, 테스트 발송, UTM 링크를 올린다.
- 목적, 대상, 가설, 검증 결과, 실패 시 내리는 방법을 기록한다.

### 7. 마케팅 CI
- 깨진 링크, 트래킹 누락, 금지 단어, 과장 광고
- 채널 스펙, 예산 한도, 수신동의, 중복 발송, 잘못된 세그먼트
- 게이트: 필수 검사를 통과해야 한다. 우회는 별도 승인이다.

### 8. 독립 리뷰
~~~text
Copy Agent A        → 초안 작성
Reviewer Model B    → 명확성, 중복, 진부함
Brand/Legal Agent C → 클레임, 규정, 톤
Analyst Agent D     → 가설과 KPI 정합성
Human               → 브랜드 리스크와 지출 승인
~~~
카피를 만든 모델이 자기 카피를 평가하면 안 된다.

### 9. 소프트 런치
- 내부 발송, 작은 세그먼트, 낮은 예산, 단일 채널부터 시작한다.
- 게이트: 게시본과 승인본 일치, 트래킹 동작, CTA 동작, 오해나 항의 없음.
- “예약 성공”과 “정상 배포”를 별도로 증명한다.

### 10. 본 집행
| 위험도 | 예시 | 게이트 |
|---|---|---|
| 낮음 | 내부 초안, 검색 리서치 | 자동 검사 |
| 보통 | 블로그, 소셜 초안 | 독립 리뷰 |
| 높음 | 외부 광고, 고객 이메일 | 다중 검토 또는 사람 승인 |
| 치명적 | 가격·성능 클레임, 대량 발송, 큰 예산 | 사람 승인 + 중단 조건 |

롤백은 git revert가 아니라 광고 중지, 게시 내리기, 메일 중단, 정정 공지다. 중단 조건은 미리 정한다.

### 11. 집행 후 관찰
- CTR, CPC, CPA, 전환, 구독 해지, 스팸 신고, 랜딩 이탈
- 이전 캠페인과 비교하고, 이상치가 나오면 자동 일시정지한다.
- 지표는 늦게 오고 노이즈가 커서 초기에 큰 자율 집행을 주면 안 된다.

### 12. 학습
- 이긴/진 메시지를 자산화하고, 반복 작업을 스킬로 등록한다.
- 금지 클레임을 정책에 추가하고, 실패를 다음 CI 규칙으로 승격한다.

## 개발보다 어려운 지점

1. 증거가 약하다. 테스트 그린은 비교적 명확하고, CTR 상승은 원인 추정이 어렵다.
2. 실패가 조용하다. 틀린 카피와 예산 낭비가 쌓인다. [[agent-process-lifecycle]]의 업무 자동화형 실패 모드와 같다.
3. 되돌리기 비용이 비대칭이다. 외부에 나간 메시지는 평판이 남는다.
4. 단일 모델이 더 위험하다. 비슷한 카피와 비슷한 사각지대가 생긴다.

따라서 마케터 에이전트의 본체는 카피 생성이 아니라 게이트와 측정이다.

## VirtOn / GPU 중개 예시

“가격 불안을 줄이는 PLG 랜딩”이라면:

- Planner: 가설과 대상 세그먼트
- Executor: 헤드라인, 비교표, CTA, UTM
- Reviewer: GPU 시간 판매가 아니라 매끄러운 AI 인프라 경험으로 읽히는지
- Legal/Claims: 성능, 가격, SLA 과장 여부
- Analyst: 데모 신청이 실제 성공 지표인지
- Approver: 소액 광고 또는 일부 세그먼트만 먼저 허용
