# 영업: 고객 관리와 제안서 (터미널 에이전트 실전)

이 문서는 Threads 연재 3편의 상세 근거 자료입니다. 코딩을 모르는 영업 담당자가 터미널 에이전트(Claude Code, Codex)에게 실제로 시켜 볼 수 있는 지시문을 그대로 담았습니다.

## 왜 앱이 아니라 터미널 에이전트인가

ChatGPT나 Claude 앱에 물어보면 답은 나옵니다. 하지만 그 답을 다시 내 엑셀에 옮겨 적는 것은 결국 내 손입니다.
터미널 에이전트는 다릅니다. 내 컴퓨터에 있는 **고객 목록 엑셀, 미팅 기록, 주고받은 이메일 파일을 직접 열어서 읽고, 고치고, 새 파일로 만들어 줍니다.** 복사해서 붙여넣는 중간 과정이 사라집니다.

정리하면 이렇습니다.

- 앱: "답을 알려주는 도구"
- 터미널 에이전트: "내 파일을 실제로 손봐서 결과물을 만들어 주는 도구"

이 문서에서 다루는 네 가지 작업 모두, 결과물이 내 폴더에 파일로 남습니다.

## 준비: 폴더 하나에 자료를 모아 둔다

에이전트는 자기가 실행되고 있는 폴더 안의 파일을 봅니다. 그래서 먼저 작업 폴더를 하나 만들고, 관련 자료를 그 안에 넣어 두는 것이 좋습니다.

예를 들어 바탕화면에 `영업2026` 폴더를 만들고 그 안에 이렇게 넣어 둡니다.

- `고객목록.xlsx` (거래처, 담당자, 지난 연락일, 상태 등이 적힌 엑셀)
- `미팅기록/` 폴더 (미팅 때 적은 메모를 텍스트나 워드로 저장)
- `이메일/` 폴더 (중요한 메일을 복사해 텍스트로 저장하거나 내보낸 파일)

그다음 터미널에서 그 폴더로 이동한 뒤 에이전트를 실행합니다. 이제 지시문에서 "고객목록.xlsx" 라고만 말해도 에이전트가 그 파일을 찾아 읽습니다.

> 주의: 고객 실명·회사명·연락처가 담긴 파일은 회사 규정과 개인정보 보호에 맞게 다뤄야 합니다. 외부로 나가는 문서에는 실명과 민감 정보를 넣지 않는 것이 원칙입니다.

## 작업 1. 뒤죽박죽 고객 목록 엑셀 정리하기

영업 목록은 시간이 지나면 표기가 제각각이 됩니다. 날짜 형식이 섞이고, 상태 칸이 비어 있고, 중복된 거래처가 생깁니다.

### 복붙용 지시문 예시

```
같은 폴더에 있는 고객목록.xlsx 파일을 열어서 아래 규칙대로 정리하고,
원본은 그대로 두고 "고객목록_정리본.xlsx" 라는 새 파일로 저장해 줘.

1. 날짜 칸(지난 연락일)은 모두 2026-08-29 형태로 통일해 줘.
2. 회사명이 중복된 줄이 있으면 가장 최근 연락일 줄만 남기고 정리해 줘.
3. 상태 칸이 비어 있으면 "확인필요" 라고 채워 줘.
4. 담당자 이름 앞뒤의 불필요한 공백을 없애 줘.
5. 무엇을 몇 건 고쳤는지 마지막에 요약해서 말해 줘.
```

### 결과가 어떻게 나오나

- 폴더에 `고객목록_정리본.xlsx` 라는 새 파일이 생깁니다. 원본은 건드리지 않습니다.
- 에이전트가 "날짜 형식 34건 통일, 중복 거래처 6건 정리, 빈 상태 칸 12건 채움" 처럼 무엇을 했는지 말로 요약해 줍니다.

### 주의점

- **반드시 "새 파일로 저장"이라고 지시합니다.** 원본을 덮어쓰면 되돌리기 어렵습니다. 지시문에 원본 보존을 명시하세요.
- 처음에는 목록 전체가 아니라 몇 줄만 시험 삼아 정리하게 해서 결과를 확인한 뒤 전체에 적용하는 것이 안전합니다.
- 정리 규칙이 애매하면 에이전트가 임의로 판단합니다. "중복이면 최근 것만" 처럼 판단 기준을 분명히 적어 주세요.

## 작업 2. 이번 주에 팔로업할 곳만 추려 내기

목록이 정리되면, "누구에게 언제 연락해야 하는가"를 매번 눈으로 훑을 필요가 없습니다.

### 복붙용 지시문 예시

```
고객목록_정리본.xlsx 를 보고, 이번 주에 팔로업해야 할 거래처만 골라 줘.
기준은 이렇게 잡아 줘.

- 지난 연락일이 14일 이상 지났고,
- 상태가 "제안중" 또는 "검토중" 인 곳.

고른 곳을 연락일이 오래된 순서로 정렬하고,
각 줄에 "회사명 / 담당자 / 마지막 연락일 / 며칠 지났는지 / 상태 / 한 줄 다음 액션"
형태로 표를 만들어서 "이번주_팔로업.md" 파일로 저장해 줘.
'한 줄 다음 액션'은 상태에 맞게 네가 제안해 줘.
```

### 결과가 어떻게 나오나

- `이번주_팔로업.md` 라는 파일이 생기고, 아래처럼 바로 볼 수 있는 표가 담깁니다.

```
| 회사명 | 담당자 | 마지막 연락 | 경과 | 상태 | 다음 액션 |
| A상사 | 김OO 부장 | 2026-08-01 | 28일 | 제안중 | 견적 재확인 메일 발송 |
| B물류 | 이OO 과장 | 2026-08-10 | 19일 | 검토중 | 도입 일정 질문 |
```

- 월요일 아침에 이 파일 하나만 열면 이번 주 우선순위가 정리됩니다.

### 주의점

- **재촉은 회로 차단기입니다.** 이미 거절했거나 답이 없어 한 번 후속했던 곳은 다시 목록에 넣지 않도록, 상태 칸에 "무응답"이나 "거절"을 적어 두고 지시문에서 그 상태는 제외하라고 말하세요.
- 무응답은 한 번만 자연스럽게 후속하는 것이 원칙입니다. 에이전트가 목록을 뽑아 줘도, 몇 번씩 재촉하는 데 쓰지 마세요.
- '다음 액션'은 어디까지나 초안 제안입니다. 실제로 보낼지는 사람이 판단합니다.

## 작업 3. 회사별 맞춤 제안서 초안 만들기

같은 상품이라도 회사마다 상황이 다릅니다. 표준 제안서를 매번 손으로 고쳐 쓰는 대신, 기준 문서 하나를 두고 회사별로 갈아 끼우게 시킬 수 있습니다.

### 준비

- 폴더에 `제안서_표준양식.md` (또는 워드)를 하나 둡니다. 회사명·상황·가격 부분을 `[회사명]`, `[상황]`, `[가격]` 같은 빈칸으로 남겨 둡니다.
- 상대 회사의 상황 메모를 `상황_A상사.txt` 처럼 저장해 둡니다.

### 복붙용 지시문 예시

```
제안서_표준양식.md 를 기본 틀로 삼고, 상황_A상사.txt 에 적힌 내용을 반영해서
A상사용 제안서 초안을 만들어 줘. "제안서_A상사_초안.md" 로 저장해 줘.

- 빈칸([회사명], [상황], [가격])은 상황 메모의 내용으로 채워 줘.
- 상황 메모에 없는 정보는 지어내지 말고 "[확인필요]" 라고 남겨 둬.
- 가격은 범위로 쓰지 말고, 상황 메모에 적힌 고정가 또는 3개 옵션으로만 적어 줘.
- 과장된 표현이나 "무조건", "최고" 같은 단정하는 말은 쓰지 마.
- 우리 회사명과 고객사 실명은 넣지 말고 [당사], [고객사] 로 표기해 줘.
```

### 결과가 어떻게 나오나

- `제안서_A상사_초안.md` 파일이 생깁니다. 표준 틀은 그대로이고 회사 상황에 맞는 부분만 채워진 상태입니다.
- 정보가 부족한 칸은 `[확인필요]`로 남아 있어, 어디를 더 채워야 하는지 한눈에 보입니다.

### 주의점

- **지어내기(환각)를 막는 문장을 꼭 넣으세요.** "없는 정보는 지어내지 말고 [확인필요]로 남겨 둬"가 핵심입니다. 이 한 줄이 있으면 잘못된 숫자가 제안서에 들어가는 사고를 크게 줄입니다.
- 가격은 범위가 아니라 고정가 또는 3옵션으로 적게 하세요. 협상의 기준이 흔들리지 않습니다.
- 나온 것은 **초안**입니다. 그대로 보내지 말고 사람이 검토·수정한 뒤 발송하세요. 발송 주체는 언제나 사람입니다.

## 작업 4. 지난 대화·이메일에서 반대 의견만 뽑아 대응 정리하기

같은 반대 의견이 여러 고객에게서 반복됩니다. 흩어진 미팅 메모와 이메일에서 반대 의견만 모아 두면, 다음 상담에서 바로 꺼내 쓸 수 있는 대응 카드가 됩니다.

### 복붙용 지시문 예시

```
미팅기록 폴더와 이메일 폴더 안에 있는 모든 텍스트 파일을 읽어 줘.
그 안에서 고객이 표현한 "반대 의견"이나 "망설이는 이유"만 뽑아 줘.
(예: 비싸다, 지금은 예산이 없다, 기존 것으로 충분하다, 도입이 번거롭다 등)

비슷한 반대 의견끼리 묶어서, 각 묶음마다 아래 형태로 정리해서
"반대의견_대응카드.md" 로 저장해 줘.

- 반대 의견 요약 (한 줄)
- 몇 번 나왔는지
- 실제 고객이 했던 표현 1~2개 인용
- 이렇게 답하면 좋겠다는 대응 예시 초안 (2~3줄)

대응 예시는 상대의 감정을 먼저 인정하고, 비슷한 사례를 들어 안심시키는 방향으로 써 줘.
없는 사례나 숫자는 지어내지 마.
```

### 결과가 어떻게 나오나

- `반대의견_대응카드.md` 파일에 이런 식으로 정리됩니다.

```
## "지금은 예산이 없다" (5건)
고객 표현: "올해 예산은 이미 다 잡혀 있어서요"
대응 초안: 예산 일정 부담을 먼저 공감하고, 다른 고객도 같은 고민을
했지만 분기 이월이나 소규모 시범 도입으로 시작한 사례를 소개.
```

- 반복되는 반대 의견이 빈도순으로 보이므로, 어디에 대응을 준비해야 하는지 우선순위가 잡힙니다.

### 주의점

- 대응 초안은 "감정을 인정하고(Feel), 다른 고객도 그랬고(Felt), 이렇게 풀었다(Found)" 흐름으로 쓰게 하면 자연스럽습니다. 다만 **없는 사례나 숫자를 지어내지 말라고 못 박으세요.**
- 반대 의견은 거절이 아니라 확신이 부족하다는 신호입니다. 대응 카드는 그 확신을 채워 주는 재료로 쓰고, 밀어붙이는 대본으로 쓰지 마세요.
- 미팅 메모·이메일에는 민감 정보가 많습니다. 이 작업은 내 컴퓨터 안에서만 돌리고, 결과 파일도 실명·회사명이 남지 않게 확인하세요.

## 이 편의 핵심 한 줄

터미널 에이전트는 "영업 답변을 대신 써 주는 도구"가 아니라, **내 고객 목록·미팅 기록·이메일을 직접 읽어서 정리·팔로업·제안서 초안·반대 대응 카드를 파일로 만들어 주는 도구**입니다. 만들어진 것은 모두 초안이고, 보내는 결정은 언제나 사람이 합니다.
